# A+ production conflicts and resolutions

Each row records a prototype behavior that must not silently replace approved
Mobile behavior.

| Lovable A+ behavior | Production authority | Chosen Flutter behavior | Reason |
|---|---|---|---|
| Home renders two fixture Recent operations. | No approved Mobile contract or repository source provides an authoritative recent-operation feed. | Omit Recent operations and preserve the surrounding A+ task-first hierarchy and whitespace. | Do not invent analytics, history, storage, or backend data. |
| Scanner uses `CameraStage`, fake QR art, and timers. | Existing camera adapters, permission flow, lifecycle, debouncing, single-flight, QR parsing, and authoritative resolution. | Apply A+ target, corners, rail, sheets, typography, and motion to the existing canonical scanner. | A visual prototype cannot replace real camera/security behavior. |
| A client-visible fixture code opens demo scenarios in every web build. | M3F debug-only local Demo routing plus server-backed production Review; no master code. | Keep the current typed manual-code router. Local Demo remains structurally debug-only; production Review remains server-backed. | Preserve production exclusion and prevent a client-side bypass. |
| Lab state jumps expose Demo and every product state. | Ordinary Mobile users must not see Demo/Review/Test/Developer/Owner entry UI. | No state-jump or Demo navigation appears in production composition. Authorized local-demo tools remain available only after M3F authorization. | Lab chrome is not product UI. |
| Pairing, Review, and local Demo share a toy manual submit function. | Existing pairing claim/challenge/proof flow and separate M3F manual-code routing. | Use one A+ manual-code presentation over the current production controllers and route semantics. | Preserve Ed25519 identity, pairing, and Review authority. |
| App Lock unlocks on any four typed digits; the Biometric button succeeds immediately. | Existing App Lock repository/controller, secure PIN handling, biometric service, delays, privacy overlay, and screenshot protections. | Rebuild only the A+ keypad, dots, messaging, and composition around real App Lock outcomes. | The prototype interaction is a visual fixture, not authentication. |
| Manager approval is a local enum; checking returns to pending, while a pending state can satisfy the toy commit branch. | Existing server-authoritative approval state machine, approval public ID, semantic operation, original idempotency key, and fresh signed transport envelope per attempt. | Retain the full current approval controller/domain behavior and restyle required/checking/pending/rejected/expired/approved recovery states. | Pending is not authorization, and Mobile never gains an Approve capability. |
| Stamp/redeem eligibility and resulting state are computed locally. | Backend-authoritative eligibility, purchase threshold, daily cap, currency/timezone, ledger, reward, and recovery semantics. | Present current authoritative controller state through A+ customer/review/success layouts. | Avoid fake mutation or optimistic success. |
| Success uses fixture request references and locally calculated progress. | Authoritative operation responses and pending-recovery records. | Show A+ success only after the existing controller confirms success; display the resulting authoritative loyalty state. | Animation cannot create product truth. |
| Offline, billing, session, and device states are local toggles and can be cleared by fixture buttons. | Existing boot/session/device/billing/error-code handling. | Preserve distinct production states and their approved safe recovery actions; use the A+ text-led notice composition. | Do not collapse or locally dismiss authoritative blocks. |
| Scanner catalog does not distinctly cover expired QR, permanently denied permission, camera unavailable, or every background/resume condition. | Existing production scanner lifecycle and error mapping. | Extend the canonical A+ scanner language to every current authoritative state. | Missing prototype states do not justify removing production behavior. |
| Home and security use fixture merchant, branch, device, version, timestamps, and capability values. | Active device context and current runtime/app metadata. | Bind A+ presentation to real existing providers; retain safe unavailable fallbacks. | Do not ship fixture identity or status. |
| A+ has no authoritative merchant-art transport. | Current Mobile contract and approved fallback behavior. | Keep the existing safe fallback unless a renderable authoritative payload already exists. | Do not invent URLs or a new backend transport. |
| Lovable brand marks resolve through its private asset proxy. | Official brand assets already tracked in Flutter. | Use the current official Flutter mark/lockup assets while matching A+ composition. | Avoid broken or unofficial identity and any runtime dependency on Lovable. |
| The lab phone is fixed at 348×720 with a fake bezel/status island. | Native Android/iOS SafeArea, device dimensions, keyboard, and accessibility insets. | Preserve A+ proportions responsively with native system insets and scrolling. | Lab framing is evidence chrome, not app layout. |
| Lab large text is a 1.55 CSS multiplier. | Required Flutter verification at approximately 200% text scale. | Use native text scaling and reflow, keeping actions reachable without shrinking type. | Accessibility adaptation takes precedence over pixel copying. |
| A+ dark semantic neutrals differ from the earlier conservative Flutter dark derivation. | A+ is the owner-selected visual authority; official constant brand colors remain locked. | Refine dark canvas/surface/raised/text/divider semantics toward rendered A+ while retaining contrast and official brand constants. | This is an authorized presentation change, not a brand or behavior change. |
| The manual screen labels the input as a pairing code even when reached from the customer scanner. | Existing localized manual-route semantics distinguish pairing/customer Review behavior where required. | Preserve correct production copy and generic hidden-entry presentation, adapting the A+ form hierarchy. | Do not mislabel a production credential merely for prototype parity. |
| Settings sends Sign out directly to the fixture pairing screen. | Existing secure sign-out/unpair/session lifecycle. | Keep current controller-backed confirmation and cleanup behavior under the A+ visual treatment. | Navigation in the prototype is not lifecycle authority. |
| Sorani/Badini show unavailable placeholders without authoritative product strings. | Authoritative localization files only. | Do not invent translations; retain/report pending locales unless reviewed files exist in the starting Mobile source. | Machine-created copy is prohibited. |

These are contract-driven or accessibility-driven deviations, not permission to
borrow replacement ideas from Directions A/B/C/D.
