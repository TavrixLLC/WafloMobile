# M2 handoff

M1 exposes stable foundations for a later operational milestone: authoritative boot/context, device-bound Ed25519 signing, exact-byte signed transport, typed API generation, localized stable errors, and explicit online-only policy.

Before M2, approve new OpenAPI operations, idempotency/replay rules, role/location authorization, risk responses, safe customer models, and real backend certification fixtures. Add no operation merely because a disabled placeholder exists.

Not implemented in M1: membership/customer QR scanning, stamp issuance, redemption, reversal, approvals, operation history, offline queues, NFC, Smart Tap/Wallet, customer login, or merchant password login.
